### 0.2 关键决策（与本计划原文的偏差）

| # | 决策 | 理由 |
|---|---|---|
| D7 | 背包**沿用 `/forge` 路径与 `forge` 路由名**，`/backpack` 只是别名（两者 `meta.tab === 'forge'`） | E2E / 截图工具 / 每日任务跳转**全部不用改**；底部导航仍是 5 个标签 |
| D19 | `normalizeItems` 以**全 0** 为起点（不是 `START_ITEMS`），且**尊重显式 0** | 原实现会让玩家清空背包后物品被自动补回（背包永远清不空） |
| D20 | 新号起始结晶 6,000（= 20 抽）；E2E 按按钮实际文案「圣杯结晶 3000」断言 | 与设计稿「新号仍有 20 抽购买力」对齐 |
| D21 | 仓库筛选只用服务端**已支持**的 `rarity` / `setId` / `sort=level` | 不臆造服务端契约 |
| D22 | 背包「强化材料」页只统计**编队内**可强化的遗物数 | 客户端镜像里只有已装备遗物，不冒充全仓库统计 |
| D23 | 喂书结果 `applied` = **本次投入**（`booksUsed × 面额`），存量另走 `expRemaining` | 原实现把英灵**全部存量经验**重复计入 → 界面显示的「投入经验」是错的 |
| D24 | `FeedBooksResult` 定义**只留一份**（`core/systems/growth.ts`），`actions.ts` 转出 | 两处各写一份必然分叉（铁律 #4） |
| D25 | 副本走**平行配置**，不进 `STAGES` | `STAGES` 有三处硬约束（单调递增 / `clearedStage ≤ 长度` / 末关判定），混进去会破难度标定的不变量 |
| D26 | 背包「五行」一律经 core 的 `itemElement()` 反推，**禁止 `id.replace('skillMat','')`** | 后缀是英文（`Fire`）而游戏内五行是中文（`火`）→ 「去副本」跳错副本 + 五行筛选全置灰 + 可用英灵统计恒 0 |
| D27 | 强化石只从**强化副本**产出 | 遗物强化的真实链路因此是「推征 → 遗物 → 强化副本 → 强化石 → 强化遗物」；E2E 走这条真实链路而非导入存档 |
| D28 | 背包「投喂」的**预览与执行共用同一截断口径** `effectiveFeedCount`；无库存时按钮禁用 | 预览多算 / 执行少算会让玩家看到「预计 +N」却只补了一半经验 |
| D29 | `tools/artgen/local-out`（gitignored 的提示词缓存）加入禁用词扫描**跳过目录** | 那是生成提示词缓存，不是对外文案；但**提示词本身仍须守规矩**（绝对化词会被画进图标） |
| D30 | 「铸造」页升级为背包后**不再自带召唤面板** | 召唤入口收在顶栏「圣杯结晶」说明弹窗；铁律 #10 仍成立（圣殿页 + 顶栏弹窗 + 新手引导三处可达） |
| D31 | 强化副本的解锁线用**服务端统计的仓库最高等级**（`GET /api/relics/stats` 的 `maxLevel`），客户端显式传给 `dungeonUnlocked` | 客户端镜像里 `save.relics` **只有已装备件**（存档分包）→ 直接从 `save.relics` 取会把「已解锁」误判成「未解锁」。统计**没读到之前不下结论**（按钮置灰 + 「正在读取仓库信息…」） |
| D32 | 模板里的强调一律用 `<b>`；**只有走 `richParts` 解析器**的文案才允许带 `**`（合规页正文 + 顶栏资源弹窗） | Vue 模板不渲染 markdown → `**` 会原样印给玩家（8 处）。新增铁律 #50 + `tests/unit/ui-text.test.ts` 守护 |
| D35 | 副本刷取口径独立成 `tools/balance/dungeon-loop.ts`，`newplayer.ts` 与 `recalibrate.ts` **共用** | 铁律 #4：同一口径只能有一份实现，两个工具各写一套必然对不上 |
| D36 | 挂机时间分配模型 = **「一夜能换多少战力」**（ln 口径，三去向可比） | 早期「缺口最大的一维就去刷对应副本」的 bang-bang 在多维缺口下会抖动；ln 口径让主线/强化/技能三条线的收益可直接比较 |
| D37 | 副本的**银两前置条件**是硬约束（副本只发材料不发银两） | 否则模拟第 2 天死锁（实测 40 天零推进） |
| D38 | **境界门槛上主线是唯一出路**（突破要银两，银两只有主线给）⇒ 门槛上主线增益 = ∞ | 经验卡在门槛不兑现；不特判就会选到「刷材料但升不了级」的死路 |
| D39 | 时间单位 = **一段完整会话**（`recalibrate` 1 天/段，`newplayer` 1 小时/段）；切分只能发生在段与段之间 | 段内让租约生效会把离线曲线重复套用，有效时长成倍膨胀 |
| D40 | 遗物维度**不受参考曲线上限约束** | 参考曲线是难度标定的尺，不是玩家养成上限；玩家按石档结构 + 边际收益自然收敛（淬炼段每级 +0.6%） |
| D41 | 回收比容差口径：存量资源取 max(一次动作, 本章每会话平均产出, 截至本章单会话产出历史最大值)；经验为流量资源只取一次喂书 | 副本模型下「产出按夜结算、消耗按结算批量发生」⇒ 跨章结转是常态；`judgeRecycle` 逻辑与其单测**不改** |
| D42 | 报告新增维度：每日挂机去向、技能平均等级、星级 | 否则「曲线为什么变了」只能靠猜 |
| D43 | `newplayer` 的材料速率改用**真实产出**（余额差会抹掉到账即被消耗的材料） | 经验维度早就踩过这个坑 |
| D44 | 40 天曲线验收标准 = 回到改造前旧基线水位且涌现阶梯偏差**不劣于**旧基线 | 副本接入是「补回真实链路」，不是「顺手把曲线调好看」 |
| **D45** | **三个去向的增益必须同单位**（全队战力相对增幅 ln 口径）：主线 = **人均**涨级；技能 = 技能等级**总数 ÷ 队伍人数**；强化 = 遗物倍率比 × **已装备遗物的英灵占比** | 技能分支漏了「÷ 队伍人数」⇒ 技能增益被系统性放大 4~6 倍 ⇒ 新号开局先刷 6 小时技能副本、主线一关不打（首日第 123 关 → 第 85 关） |
| **D46** | **银两瓶颈必须进增益口径**：技能每级 800 银两、遗物每级 500 银两 ⇒ 一夜能升多少级取决于**买得起多少**，不是「材料够多少」 | 副本只发材料不发银两；只按材料算 ⇒ 模型会说「一夜买满全部剩余技能」，而玩家买不起（实测 50,000 银两只够 62 级，模型按 120 级算） |

### 0.3 实施中发现并修掉的既有缺陷

1. **`normalizeItems` 把玩家清空的背包自动补回**（见 D19）。
2. **`FeedBooksResult.applied` 重复计入存量经验**（见 D23）。
3. **`FeedBooksResult` 在两处各有一份定义**（见 D24）。
4. **技能升级扣错资源**的历史命名坑被彻底关掉：
   `crystals` 现在**专指圣杯结晶**，术式结晶一律叫 `skillStones`，
   遗物强化石叫 `relicStones`——而这三个现在都已退役，
   养成材料统一进 `save.items`（`skillMat*` / `relicStoneTier*`）。
5. **背包页的五行反推用错了口径**：写的是 `def.id.replace('skillMat','')`，
   得到英文后缀（`Fire`）而游戏内五行是中文（`火`）→
   「去副本」跳错副本 + 五行筛选全置灰 + 可用英灵统计恒 0。
   改为 core 的 `itemElement()` 单一入口（D26）。
6. **副本页把内部 id 当玩家文案显示**：强化石档位直接印 `relicStoneTier1`。
   改为 core 的 `dungeonVariantLabel()`（显示「初阶」）。
7. **强化副本的解锁判定用了客户端看不见的数据**：
   `dungeonUnlocked` 从 `save.relics` 取最高等级，而客户端镜像里
   `save.relics` **只有已装备件** → 玩家明明有 Lv60 遗物，
   副本页却一直显示「需要持有 Lv60 遗物（当前最高 Lv0）」且按钮点不动。
   改为服务端统计仓库最高等级并显式传入（见 D31）。
8. **模板里残留 markdown 粗体语法**（截图验收发现，单测与 E2E 全绿也没拦住）：
   Vue 模板**不渲染 markdown**，`**只发所选材料**` 会被**原样印给玩家**
   （副本页 / 背包页 / 竞技页 / 每日页 / 召唤页 / 设置页共 8 处）。
   改为 `<b>…</b>`；顶栏资源弹窗改为复用合规页那份 `richParts` 解析器。
   由 `tests/unit/ui-text.test.ts` 守护（新增铁律 #50）。

### 0.6 第二轮：材料副本刷取进入节奏模拟口径（2026-11-20）

**背景**：§0.4 留下的「已知未跟上 ①」——`recalibrate` / `newplayer` **只跑主线、不刷副本**。
v10 把五行技能材料 / 三档强化石改成**副本专属产出**之后，
模拟英灵永远升不了技能、强化不了遗物 ⇒ 40 天只到第 247 关
（改造前旧基线是到第 309 关、卡在最终 BOSS 第 310 关）。
**那条曲线测的是一个不存在的游戏。**

#### 0.6.2 挂机去向的决策模型

**「一夜能换多少战力」**（ln 口径）——三个去向放在一起比：

| 去向 | 增益（ln） | 换算 |
|---|---|---|
| 主线 | `人均涨级 × ln(LEVEL.MULT)` | 经验书 → 等级 → 战力 ×1.03/级 |
| 技能副本 | `技能等级总数 ÷ 队伍人数 × 0.02 / 技能倍率` | 五行材料 → 技能等级 → 技能强度 |
| 强化副本 | `ln(遗物倍率比) × 已装备遗物的英灵占比` | 强化石 → 遗物等级 → 主词条倍率 |

**三条防死锁约束**（否则模拟会自锁）：

1. **副本必须已解锁**（core 的 `dungeonUnlocked`）——不替玩家开挂；
2. **银两必须够下一次升级**——副本**只发材料不发银两**，银两不够还去刷副本 = 白刷一天；
3. **境界门槛上主线是唯一出路**——经验卡在门槛不兑现，突破要银两而银两只有主线给
   ⇒ 门槛上主线增益 = ∞。

**时间单位 = 一段完整会话**（`recalibrate` 1 天/段、`newplayer` 1 小时/段）：
一段离线期的有效时长是**一整块**，期间切去向只会让这一整块按**旧去向**结清
⇒ 切分只能发生在段与段之间；段内**不得**让租约生效（否则离线曲线被重跑一遍、
有效时长成倍膨胀）。

#### 0.6.3 本轮实测抓出的两处模型口径错

| 错 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **技能增益漏了「÷ 队伍人数」** | 新号开局先刷 6 小时技能副本、主线一关不打；首日进度从第 123 关掉到第 85 关 | `bought` 是**受影响英灵**的技能等级总数，直接当全队增益用 ⇒ 系统性放大 4~6 倍 | 三个去向统一成「全队战力相对增幅（ln）」：主线 = 人均、技能 = 总数 ÷ 队伍人数、强化 = 倍率比 × 装备占比 |
| **副本难度自适应晚一天生效** | 「降一档难度」要等一天，40 天里白打约 2 天 | `recalibrate` 的日循环是「先决策明天的去向、**后**更新难度」 | 把难度自适应挪到决策**之前**（`newplayer` 每段开头决策、段尾更新难度，顺序天然是对的） |

> 附带修掉：`newplayer.ts` 的 `advanceIdle` 返回类型漏了 `materials`（`vue-tsc` 报错）。

#### 0.6.5 已知建模残留（不是功能缺陷）

- **副本难度按「战力门槛」选**（与主线放行同一把尺），而战力门槛比**真实战斗**乐观
  ⇒ 模拟玩家会「顶格 → 被卡 → 降档 → 再顶格」地震荡，40 天里约 2 天卡在副本波次上。
  core 给的出口就是「降一档难度」（设计稿），模拟照做；
  彻底消除要换成**实战二分**（成本高，留作后续）。
- **模拟玩家星级恒为 1**（主线不产同名碎片，模拟未建模抽卡经济）——
  这是模拟战力低于标定参考队伍（star 5~6）的结构性原因，与副本口径无关。
- **回收比容差口径**（D41）：副本模型下「产出按夜结算、消耗按结算批量发生」
  ⇒ 跨章结转是常态，容差取
  `max(一次消费动作, 本章每会话平均产出, 截至本章单会话产出历史最大值)`；
  经验是流量资源，只取一次喂书。`judgeRecycle` 的逻辑与其单测**未改**。

## 2. 建立钱包、背包与旧档迁移

钱包只承载两种余额。普通材料按「道具定义 × 数量」入包，同名碎片按英灵定义分堆；遗物继续使用原实例 UID、词条、锁定和装备绑定。保留已装备镜像和遗物服务端分页；批量发奖以 `RewardBundle` 为唯一来源，统一处理钱包、堆叠物、遗物和溢出回报。账号首通记录与本周目进度分开保存。

| 旧档数据 | 建议迁移策略与核对 |
|---|---|
| 银两、圣杯结晶、抽卡券 | 两种余额承接原值，每张未用券增加 300 结晶。核对迁移前后可抽次数 |
| 玩家经验池、英灵个人经验 | 玩家池按大、小书面值折书，尾差向上补足一本小书；单账号补差低于一本小书。英灵个人经验原值保留，包括境界门槛上的进度 |
| 英灵碎片、英灵印记 | 碎片按原英灵逐项入包；印记按旧突破购买力定表折银两。分别列示两项，已培养的等级与星级完整保留 |
| 旧术式结晶、旧强化石 | 先算旧余额可支持的升级次数，再换算为新材料。建议给予一次性选择分配五行或石档的旧档权益，按统一折算表结算，已分配数量立即核销。权益仅服务迁移；记录原额、已兑与待兑，避免强塞无用材料或按件数放大高阶价值 |
| 遗物、竞技余额 | 原 UID、等级（含 131～200）、词条、装备、锁定逐件核对。旧竞技勋章、竞技材料记录在只读历史摘要，段位和称号照原档承接 |
| 已通主线 | 建议按可信服务端通关进度补发本版新增的首通结晶，并在同一事务登记。重试、换设备及后续重启均读同一记录。旧进度缺失单列记录；客户端导入数据不能作为历史补偿凭证 |

迁移先用数据库副本演练，覆盖空档、普通号、高养成老号、已重启账号和可导入的旧格式。版本升级、到账明细和补发标记同事务写入；迁移过程可重试。发布前定稿折算表和补偿总量，验证备份恢复后逐项对账。平台侧只写本账号的只读缓存。

## 3. 接通产出与消耗

| 顺序 | 改动 | 完成条件 |
|---|---|---|
| ① 抽卡与养成 | 抽卡沿用 `resolvePayment()` 单一扣费入口，仅扣结晶；保底与同批逐张判新继续共用原规则。喂书、升星、突破、升技能、遗物强化和分解走 core 纯动作与服务端权威事务 | N 至 SSR 均能获取和消耗同名碎片；喂书正确处理满级、境界和批量。技能匹配英灵五行。批量强化逐目标等级报价，任一材料不足时整笔拒绝 |
| ② 主线掉落与首通 | 关卡奖励按关卡和首通资格计算；发放经验书、银两、遗物，以账号首通记录决定结晶。首页、关卡详情与结算使用同一份配置及报价 | 首通、复刷、离线多关、战败回刷、重启、观战和并发请求的结果正确。未胜利的关卡不计入首通，复刷不重复发结晶 |
| ③ 两类材料副本 | 增加挂机目标选择动作。服务端先用旧目标结算切换前的时间，再保存新目标。副本胜利只发所选的五行材料或石档；副本进度与主线记录分别记账 | 在线、离线及多端切换均共用一份时间账本，切换不增发场次；可正常切回主线原关。副本失败、空队、预算不足均有可见提示 |
| ④ 周边奖励与重启 | 调整开局、签到、日常、周目标、回流、竞技场、三队天梯、兑换码和重启。同步领奖类型白名单、周预算与公示。清点所有仍会写入退役资源的路径 | 新号到首次十连、日周切换、回流及重启都可走通。重启预览列明将重置的进度，已确认保留的星级、背包与账号首通记录能在执行后对账 |

沿用 `POST /api/action`、账号串行队列、幂等日志及权威时钟。涉及随机的掉落及抽卡均经服务端存档 RNG；观战预览沿用独立序列。新动作答复或老动作回执重放时，要验证旧版本客户端能识别结果或收到明确的刷新提示。

## 4. 把仓库扩成玩家可用的背包

- 保留现有遗物只读分页接口，补齐服务端分类、筛选与稳定排序；材料和碎片用堆叠清单读取。钱包、材料数量与遗物详情分别读取，避免每次动作或心跳都传回整座仓库。核心统一产出道具来源、可用对象、升级报价及差额，由界面展示。
- 连接主导航、推征、副本、英灵详情和背包。实现「缺哪种材料 → 带筛选前往对应副本 → 结算 → 回到原英灵或遗物」。点经验书可选择英灵，点碎片可查看升星条件。窄屏优先显示分类、持有量和主操作。
- 遗物强化、锁定、批量分解和满仓溢出继续遵守现有保护规则；排序、筛选、翻页之后操作仍按 UID 定位。离线缓存展示上次同步结果，任何扣费或领奖都要取得服务端回包。
