# 资源、背包与材料副本实现计划

2026-11-19 · 待实施。玩法和物品来源统一以[资源设计稿](resource-backpack-design.md)为准。本计划描述如何从现有权威存档、主线挂机和遗物仓库迁移到目标版本。

## 1. 先定投放表与兼容口径

- 从当前版本记录三组参照：新号首日成长、每日上线一次的离线成长、40 天养成模拟。分别保留首抽次数、每章耗时、首次突破、遗物件数、升星与技能投入、银两净流量、末章实战胜率。把后续新旧对照放在相同的登录频率与阵容条件下。
- 建一份配置表，登记两种货币、两种书、五行材料、三档石、英灵对应的碎片和遗物定义。现有资源名称、图标辅助函数和遗物定义继续作为各自的唯一出处。新增道具名称、图标、用途、来源和筛选标签要能从定义推导。
- 数值试算覆盖每章首通结晶总额、签到长期抽数、两种书的面值、各副本难度与掉量、遗物频率、各稀有度重复转化、各星碎片成本、银两突破费。另列签到券折算和竞技券退场后的周抽数，测满星后重复卡的比例，供定表时判断。
- 对照原基线 §5、§7、§10、§12 及项目约定中的重复补偿、经验池、材料名称、竞技周预算和任务奖励类型。实施时给受影响章节追加实施修正，同步兑换码、抽卡公示和游戏指南；保留既有历史记录。

## 2. 建立钱包、背包与旧档迁移

钱包只承载两种余额。普通材料按「道具定义 × 数量」入包，同名碎片按英灵定义分堆；遗物继续使用原实例 UID、词条、锁定和装备绑定。保留已装备镜像和遗物服务端分页；批量发奖以 `RewardBundle` 为唯一来源，统一处理钱包、堆叠物、遗物和溢出回报。账号首通记录与本周目进度分开保存。

| 旧档数据 | 建议迁移策略与核对 |
|---|---|
| 银两、圣杯结晶、抽卡券 | 两种余额承接原值，每张未用券增加 300 结晶。核对迁移前后可抽次数 |
| 玩家经验池、英灵个人经验 | 玩家池按大、小书面值折书，尾差向上补足一本小书；单账号补差低于一本小书。英灵个人经验原值保留，包括境界门槛上的进度 |
| 英灵碎片、英灵印记 | 碎片按原英灵逐项入包；印记按旧突破购买力定表折银两。分别列示两项，已培养的等级与星级完整保留 |
| 旧术式结晶、旧强化石 | 先算旧余额可支持的升级次数，再换算为新材料。建议给予一次性选择分配五行或石档的旧档权益，按统一折算表结算，已分配数量立即核销。权益仅服务迁移；记录原额、已兑与待兑，避免强塞无用材料或按件数放大高阶价值 |
| 遗物、竞技余额 | 原 UID、等级（含 131～200）、词条、装备、锁定逐件核对。旧竞技勋章、竞技材料记录在只读历史摘要，段位和称号照原档承接 |
| 已通主线 | 建议按可信服务端通关进度补发本版新增的首通结晶，并在同一事务登记。重试、换设备及后续重启均读同一记录。旧进度缺失单列记录；客户端导入数据不能作为历史补偿凭证 |

迁移先用数据库副本演练，覆盖空档、普通号、高养成老号、已重启账号和可导入的旧格式。版本升级、到账明细和补发标记同事务写入；迁移过程可重试。发布前定稿折算表和补偿总量，验证备份恢复后逐项对账。平台侧只写本账号的只读缓存。

## 3. 接通产出与消耗

| 顺序 | 改动 | 完成条件 |
|---|---|---|
| ① 抽卡与养成 | 抽卡沿用 `resolvePayment()` 单一扣费入口，仅扣结晶；保底与同批逐张判新继续共用原规则。喂书、升星、突破、升技能、遗物强化和分解走 core 纯动作与服务端权威事务 | N 至 SSR 均能获取和消耗同名碎片；喂书正确处理满级、境界和批量。技能匹配英灵五行。批量强化逐目标等级报价，任一材料不足时整笔拒绝 |
| ② 主线掉落与首通 | 关卡奖励按关卡和首通资格计算；发放经验书、银两、遗物，以账号首通记录决定结晶。首页、关卡详情与结算使用同一份配置及报价 | 首通、复刷、离线多关、战败回刷、重启、观战和并发请求的结果正确。未胜利的关卡不计入首通，复刷不重复发结晶 |
| ③ 两类材料副本 | 增加挂机目标选择动作。服务端先用旧目标结算切换前的时间，再保存新目标。副本胜利只发所选的五行材料或石档；副本进度与主线记录分别记账 | 在线、离线及多端切换均共用一份时间账本，切换不增发场次；可正常切回主线原关。副本失败、空队、预算不足均有可见提示 |
| ④ 周边奖励与重启 | 调整开局、签到、日常、周目标、回流、竞技场、三队天梯、兑换码和重启。同步领奖类型白名单、周预算与公示。清点所有仍会写入退役资源的路径 | 新号到首次十连、日周切换、回流及重启都可走通。重启预览列明将重置的进度，已确认保留的星级、背包与账号首通记录能在执行后对账 |

沿用 `POST /api/action`、账号串行队列、幂等日志及权威时钟。涉及随机的掉落及抽卡均经服务端存档 RNG；观战预览沿用独立序列。新动作答复或老动作回执重放时，要验证旧版本客户端能识别结果或收到明确的刷新提示。

## 4. 把仓库扩成玩家可用的背包

- 保留现有遗物只读分页接口，补齐服务端分类、筛选与稳定排序；材料和碎片用堆叠清单读取。钱包、材料数量与遗物详情分别读取，避免每次动作或心跳都传回整座仓库。核心统一产出道具来源、可用对象、升级报价及差额，由界面展示。
- 连接主导航、推征、副本、英灵详情和背包。实现「缺哪种材料 → 带筛选前往对应副本 → 结算 → 回到原英灵或遗物」。点经验书可选择英灵，点碎片可查看升星条件。窄屏优先显示分类、持有量和主操作。
- 遗物强化、锁定、批量分解和满仓溢出继续遵守现有保护规则；排序、筛选、翻页之后操作仍按 UID 定位。离线缓存展示上次同步结果，任何扣费或领奖都要取得服务端回包。

## 5. 验收与发布

| 验收层 | 发布前要看到的结果 |
|---|---|
| 规则与边界 | 小、大书能用于所有职业；每个五行都测一次正选和错选材料。覆盖 59→60、60→61、129→130、130→131、199→200、满级和跨两档批量强化。货币或材料不足时余额、进度和装备均无变化 |
| 真实玩家链路 | 新账号抽卡编队 → 主线首次胜利收书并升级 → 复刷无结晶 → 指定五行刷材料并升技能 → 对应档位刷石并强化 → 返回卡关处。另验同批重复与升星、换设备幂等、离线多关、满仓保护、旧档迁移两次及重启 |
| 体验与经济 | 对比主线、技能、强化三种挂机时间分配；测每小时有效升级次数、各档石等待时间、缺银两时长、每小时需要查看的遗物件数。用低星主力实战验证主线可达性；复核 200 级淬炼成本、遗物分解回收和竞技归一化 |
| 检查与部署 | 实施后跑 `npm run check`、`npm run balance:report`、`npm run balance:newplayer`、`npm run balance:recalibrate` 和相关战斗、天梯及 E2E。截图和 E2E 使用隔离端口及测试账号。先演练备份恢复，再协调服务端与客户端发布；对账首通重复发放、离线收益、迁移差额与旧客户端错误 |

**进入实现前需定表**　策划确认经验书面值、升星及升级成本、副本解锁与耗时、遗物掉率、主线首通与长期结晶预算、旧档折算及历史补发。程序可先按本计划准备可配置规则与测试样本，正式数值以模拟和实战复采结果为准。
