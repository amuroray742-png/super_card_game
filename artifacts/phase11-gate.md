## 1. 闸门判据与实测

判据阈值集中在 `PVP_SAMPLE_THRESHOLDS`（不散落到工具、文档、测试三处）。

| # | 判据 | 阈值 | 实测 | 结论 | 依据 |
|---|---|---|---|---|---|
| G1 | 样本量 | ≥ 200 | 240/组 | ✓ | 低于此数量的胜率结论不可用于决策 |
| G2 | 养成隔离：归一化后战力差 | ≤ 15% | **0.00%** | ✓ | §15.1「养成隔离」 |
| G3 | 胜率偏差（镜像对局进攻方） | ≤ 5pp | 5.00pp | ✓（贴边） | 镜像应当五五开 |
| G4 | **先手偏差（先手方 vs 后手方）** | ≤ 5pp | **76.67pp** | **✗** | 镜像里唯一的变量就是先后手 |
| G5 | 真实玩家样本 | ≥ 200/桶 | **0** | **✗** | plan.md §6.12：PvP 平衡需要真实玩家数据 |

### G2 的实测细节（隔离是真的）

| 口径 | 高养成账号 | 低养成账号 | 差 |
|---|---|---|---|
| PVE 队伍战力 | 14,844,820 | 6,072 | **99.96%**（约 2400×） |
| 竞技队伍战力（归一化后） | 4,718 | 4,718 | **0.00%** |

PVE 侧差 2400 倍，竞技侧**逐字节相同** —— 隔离在类型层面就断了
（`buildArenaLoadout` 只读星级与技能等级，等级 / 经验 / 遗物强化 / 永久加成根本进不来）。

### G4 的实测细节（这是硬阻塞）

镜像对局（同一份竞技快照双方对打）里，**唯一的变量就是先后手**：

| | 胜率 |
|---|---|
| 先手方 | **88.33%** |
| 后手方 | 11.67% |

即：**先手值 76.67 个百分点**。竞技模式已经用「按对局种子掷签」保证了
§6.9 的**双方对称**（双方各 50% 拿到先手，聚合胜率 45~50%），
但「拿到先手」这件事本身值 3/4 场——意味着：

> 若现在上真实 PvP 爬梯，**段位分衡量的会是掷签结果，不是战术水平**。

这在 Phase 11 里是致命的：玩家会认为「段位靠运气」，运营会认为「段位不可信」。

## 2. 采集器在本轮挖出的两个已上线缺陷（已修）

闸门不是走过场——它挖出了**当前版本就存在**的两个竞技场缺陷。

### 缺陷 A：多队伍镜像对局恒判负（玩家天天「挑战失败」）

| 项 | 修复前 | 修复后 |
|---|---|---|
| 3 人队打满 30 回合 | **100%** | 0%（17.8 回合打完） |
| 3 人队进攻方胜率 | **0.0%** | 51.0% |
| 满编 6 人队进攻方胜率 | **1.7%** | 51.5% |
| 6 人 4★12 技能进攻方胜率 | 57.0% | 51.5% |

**根因**：竞技是归一化数值，§6.8 的定位模板血量高、伤害低，
3 人以上的队伍**在 30 回合里打不完** → 双方都还活着 →
战斗循环按回合上限退出 → `win` 停在默认值 `false` → **进攻方被判负**。
玩家看到的是「天天挑战失败」：勋章只给 3 枚（胜利 12 枚）、永远拿不到抽卡券。

**修法**（三处，都在配置与竞技层，不动 PVE）：
1. `ARENA_TEMPLATES` 整体标定到 **攻 ×1.6 / 防 ×1.5 / 血 ×0.65**（§6.8 实施修正）；
2. `ARENA_CAPS.MAX_ROUNDS = 45`（竞技专属回合上限）；
3. 回合上限仍用尽时**按双方剩余血量比例判胜**（`BattleResult.hpById` 提供依据），
   并在竞技场页把这条规则写给玩家看。

标定口径：`npm run balance:pvp`（240 场/组），不手填。

### 缺陷 B：进攻方恒定先手（违反 §6.9 双方对称）

同速时 `a_<英灵>` 恒定排在 `e_<英灵>` 前 → 进攻方**永远先手**
→ 镜像对局进攻方胜率 76~93%。

**修法**：竞技模式按**对局种子掷一次签**决定先手权（双方各 50%）。
- 不用「按回合奇偶交替」：那样胜负会取决于**最后一回合的奇偶**，
  实测同一套阵容在不同参数下进攻方胜率在 0.5%~87.5% 之间乱跳（是奇偶，不是实力）；
- PVE 不掷签：我方固定先手是主线「打不过就回去刷」的预期手感。

修完：镜像对局进攻方胜率 48~53.5%，先手权分布 35~65%。

### 顺带修掉的「第二份配置」

`tools/balance/simulate.ts` 里**硬编码了一份竞技模板副本**，
改 `economy.ts` 也不会生效 —— 隔离阈值等于「对着旧模板测新模板」（铁律 #4）。
现在改为直接引用 `ARENA_TEMPLATES`。

## 4. 决策

| 范围 | 决策 | 理由 |
|---|---|---|
| Phase 11 **玩法**（匹配 / 攻防 / 铭文 / 赛季 / 举报） | **不启动** | ① 先手值 76.67pp，段位分会衡量掷签结果；② 真实玩家样本为零，没有可用的平衡基线；③ 玩法层工作量不小，不如先把测量基建与真实样本跑起来 |
| **测量基建**（采集口径 / 判据 / 采样管线 / 样本表） | **启动** | 本轮已落地 core 判据与合成采集器；真实采集只差「服务端落库 + 默认关闭的开关」 |
| **竞技场自身的缺陷** | **已在本轮修完** | 缺陷 A/B 都影响**当前版本**的玩家体验，不是 Phase 11 的事 |

## 5. 重新评估（复审）的触发条件

满足**全部**条件后重新走一次闸门：

1. **真实玩家样本**分桶（段位 × 竞技等级 × 时间窗）每桶 ≥ 200，且 G2/G3 在各桶都达标；
2. **先手规则**定案并落地，且镜像先手值压到 **≤ 10pp**（或明确接受并对后手方做补偿）；
3. 铭文、匹配、攻防快照、服务端幂等结算、举报五件套落地；
4. **多账号真实攻防 E2E** 通过（§15.2 第 5 条：竞技产出到账且 PVE 侧银两/经验/强化石数值未变）。

> ⚠ 合成样本**永远不能**替代真实样本做这个决策。合成对手是脚本摆的，
> 不含人类的针对性换阵；它只能用来发现结构性偏差（这一轮就挖出了两个）。

## 6. 本轮没做什么

- **没有**实现 Phase 11 的任何玩法（匹配 / 攻防 / 铭文 / 赛季 / 举报）；
- **没有**做真实样本落库（采集开关默认关闭，方案见 [pvp-sampling.md](pvp-sampling.md)）；
- **没有**给竞技场加「扫荡 / 一键跳过」；
- **没有**把天梯接入竞技铭文（铭文本身是 Phase 11 的能力）。
